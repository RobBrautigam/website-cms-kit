Website CMS Kit

Try the admin in your browser

A working demo of the kit's admin: invite-only sign-in with two-factor, a posts list with search and filters, a rich-text editor with autosave, staging and approval with a preview of the whole site, media, team, redirects and a full audit log.

Open the interactive demo

The sign-in form is pre-filled and any password works. The two-factor code is 123456.

Sample data only. The demo runs entirely in your browser. Everything you see is invented, it is saved only in this browser's local storage, and nothing is sent anywhere: there is no server, no database and no real account. The production version of every screen is the Next.js and Supabase code in the source tree on GitHub.

A five-minute walkthrough

  1. Sign in. Press Sign in, then enter 123456. (The two-factor step also shows a sample recovery code: using one turns two-factor off and sends you to set it up again, the same as the real kit.)
  2. Edit a live post. Open "Release notes: faster image uploads and alt text reminders". Change a heading, add a link, insert an image. The live site keeps the published version; your edit is a staged change, and the "Saved in this browser" note shows autosave working.
  3. Ask for a review. Press Request review. You cannot approve your own change, so the demo offers "Demo: approve as" a teammate (in the kit, the teammate signs in and approves it). "How we review a post before it goes live" is waiting for your approval: approve it from the editor or the Staging page.
  4. Preview before anyone else sees it. Open Staging. Press Compare to see the live and staged versions side by side, then flip the whole site between Live site and Staging.
  5. Publish. Tick the changes you want and press Publish selected, or use Publish now in the editor. A change still in review cannot be published until someone approves it. You can also schedule a post for later.
  6. Media. Upload an image in the media library (proposed; it stays in your browser, resized), add alt text, and use it as a featured image.
  7. Team. Invite someone, change a role, turn someone's access off. Try to demote the last super admin: the kit refuses.
  8. Audit log. Every step above is there, with who, what and when. Filter it and export a CSV.
  9. Redirects. Add a redirect, then try the proposed tester: test a path against your rules and see loops and chains caught before they ship.
  10. Start over. "Reset demo data" in the sidebar puts everything back.

In the kit today, and what is proposed

Most of the demo mirrors code that is in the kit's source today. A few screens preview features that are proposed but not built yet; the demo marks each one Proposed.

In the kit todayInvite-only sign-in, two-factor and recovery codes, posts with drafts, scheduling, a per-post preview and local autosave, the rich-text editor, image upload, staged edits on live posts with request review and approve, the staging page with compare and publish-selected, team management, the audit log with CSV export, and redirects.
Proposed, shown in the demoThe media library page, resending or cancelling an invite, and the redirect tester with its extra checks.
Demo-only helpersThe light and dark theme switch (the kit documents how to add it), viewing the admin as another role, approving as a teammate, and reset demo data.

What the real kit adds

Three security layersA proxy that checks the session, a server gate on every page and action, and Postgres row-level security as the final word.
Real accountsSupabase Auth with invite-only sign-up, TOTP two-factor, bcrypt-hashed recovery codes and password reset.
Two SQL filesThe first migration stands up the tables, policies, audit log and image bucket on a fresh Supabase project; the second adds staging and approval. The public site never reads a staged row.
